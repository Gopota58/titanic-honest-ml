# Кампания 2026-09-10: честная попытка пробить 0.81100

Цель: на имеющемся честном рекорде **0.81100** (`cand_3keycvw.csv`, RF 3-ключевой cv-взвешенный
бленд) проверить, можно ли его поднять **честно** (без утечки меток / LB-probing / фейка). Выделено
**10 посылок**: 9 экспериментальных + 1 резервная под публикацию лучшего результата.

Процесс по шагам для каждого эксперимента: улучшил → прогнал синтетику **100 раз** (варьирование
сидов OOF family-survival и модели, контроль `test_rate` и стабильности) → 1 посылка на Kaggle →
дождался реального LB → выводы.

## Движок

`campaign.py` (`Revolution`, приватный репозиторий): воспроизводит C2 **точно** (selftest diff = 0 строк),
параллельная синтетика 100× через `joblib`/`sklearn.utils.parallel`, отправка и ожидание LB
через Kaggle CLI. Методология не тронута: сглаженный OOF family-survival (α=10) + регуляризованные
деревья RF + cv-взвешивание (softmax по OOF-CV), `test_rate` ≈ 0.30.

## Выводы

- **0.81100 — жёсткий честный потолок данной методологии.** 6 из 9 экспериментов тирятся с C2,
  причём E4/E5/E9 с **diff = 0 строк** — cv-взвешивание корректно обнулило слабые 4-е ключи
  (`cabin_letter`, `ticket_prefix`) и title/deck-ключи, вернув ровно C2. Ни одна честная вариация
  рекорд не побила.
- **Добавление фич (title/deck/titledeck) к 3-ключевому бленду не бьёт базу** — меняет те же ~6 строк
  с нулевым чистым приростом (хрупкий пик «плавает» вокруг одной точности). 3-ключевая base уже
  исчерпала этот сигнал.
- **Bagging (E7) и подстройка leaf (E8) ВРЕДЯТ:** усреднение 5 сидов «размывает» хрупкий пик прочь от
  оптимума, leaf=20 роняет OOF-CV и LB. Одиночный seed=0 / leaf=10 (C2) — локальный максимум;
  любое отклонение от него ухудшает. Ещё одно подтверждение: рекорд — **хрупкий пик**.
- Синтетика 100× держала `test_rate` 0.299 везде (ворота пройдены), но **не предсказала LB** —
  единственный арбитр по-прежнему только реальный Kaggle public LB.

## Кампания 2026-09-11: OOF-stacking зонды (окончательное подтверждение)

Цель: закрыть **последнее** не опробованное честное направление из Next Steps — **аккуратный
OOF-stacking** (мета-модель на out-of-fold вероятностях устойчивых RF-ключей + base-фичи,
без утечки меток теста). Движок `campaign2.py` (импортирует `campaign.py`; `build_one_key`
возвращает честные OOF-вероятности). Лимит на 2026-09-11 свежий (10 посылок).

Процесс: сгенерирован пул зондов (мета LogReg/RF/ET на OOF-стеке 3–5 семейных ключей), каждый
прошёл `test_rate`-гейт (0.299, рабочая зона) и отправлен на реальный LB.
