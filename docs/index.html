Без утечки меток · без LB-probing · без фейка

Честное поднятие public leaderboard на классическом датасете Kaggle Titanic (891 обучающих / 418 тестовых) безо всякой утечки меток. Финальный результат — 0.81100 на публичном LB (доказанный честный потолок ~0.81–0.82).

Единственный честный арбитр качества здесь — реальный Kaggle public LB. Любая локальная валидация (cross-validation, holdout, даже синтетика с известной истиной) систематически лжёт из-за семейной структуры выборки и covariate shift.

Победная конфигурация (cand_3keycvw, 0.81100)

  • RandomForest, 3-ключевой cv-взвешенный бленд (nm_ticket + ticket + lastname)
  • базовые фичи + сглаженный OOF family-survival (alpha=10)
  • мелкие деревья (depth=10 / leaf=10), test_rate ~0.30

Методология в двух словах

Единственный сигнал, честно обобщающийся на тест, — сглаженный OOF target-encoding выживаемости семьи (family-survival, α=10). Ключ группировки — номер билета (ticket) и его вариации (nm_ticket = lastname|ticket); билет — самый чистый семейный прокси.

Рабочая архитектура: регуляризованные деревья (RandomForest / ExtraTrees), мульти-ключевой бленд с cv-взвешиванием (вес ключа = softmax от его OOF-CV точности), базовые фичи, контроль test_rate ≈ 0.30. Нарушение любого пункта → covariate-shift коллапс.

Как воспроизвести

pip install -r requirements.txt

# 1) Базовый артефакт (ET-бленд, 0.80143):
python src/make_blend.py

# 2) RF-бленд (0.80382):
python src/gen_robust.py          # -> robust_rf2.csv

# 3) Финальный кандидат (0.81100):
python src/gen_next6.py            # -> cand_3keycvw.csv

# Отправка на Kaggle (требует KAGGLE_USERNAME / KAGGLE_KEY):
python -m kaggle competitions submit -c titanic -f submissions/cand_3keycvw.csv \
  -m "RF 3-key cvw blend, public LB 0.81100"
