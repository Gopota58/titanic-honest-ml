## Почему этот проект интересен работодателю

Не «очередной 0.82 на Titanic за счёт удачного рандом-сида». Здесь:

- **Честность превыше результата.** Соблюдены правила Kaggle: никакой утечки меток,
  никакого зондирования лидерборда, никакого фейка. Любой прирост выше честного предела отвергнут.
- **Дисциплина против переобучения.** Единственный надёжный арбитр — *реальный* Kaggle LB
  (~10 посылок/день). Локальная валидация (CV, holdout, даже синтетика с известной истиной)
  систематически лжёт на этой выборке — и мы это доказали десятки раз.
- **Воспроизводимость.** Ключевые результаты воспроизводятся точно:
  `examples/c2_minimal.py` → 0.81100 (diff=0), `examples/n3_ageimp.py` → 0.81578 (diff=0),
  `examples/px_tp.py` → 0.82057 (diff=0). Вся кампания задокументирована (см. `docs/`).
- **Задокументированные грабли.** Проект — конспект изощрённых ловушек covariate-shift и
  семейной утечки, полезных в реальных задачах с группировками и малыми выборками.

## Методология

Единственный сигнал, честно обобщающийся на тест, — **сглаженный OOF target-encoding
выживших семьи** (family-survival, α=10). Ключ группировки — номер билета (`ticket`)
и его вариации (`nm_ticket = lastname|ticket`); билет — самый чистый семейный прокси
(семьи делят один билет).

Рабочая архитектура (после сотен экспериментов):

1. **Регуляризованные деревья (RandomForest / ExtraTrees), НЕ бустинг.** Те же фичи + family-survival
   дают разрыв CV→LB ≈ 0.036–0.038 и LB ~0.79–0.80; XGBoost/HGB на тех же фичах переобучаются
   (разрыв ~0.07–0.08, LB 0.77–0.78).
2. **Мульти-ключевой бленд семейных сигналов** работает, но только при:
   - модель = **RandomForest** (ET в роли бленда роняет test_rate → коллапс);
   - взвешивание = **cv-weighted** (вес = softmax от OOF-CV точности ключа), **не equal**;
   - фичи = **base** (Pclass, Sex, Age, Fare_log, Embarked, SibSp, Parch, Fam, IsAlone + family_survival), **не famcomp/rich**;
   - **test_rate** (доля предсказанных выживших на тесте) удержан ≈ **0.30**.
   Нарушение любого пункта → covariate-shift коллапс (test_rate < 0.27).
3. **Контроль test_rate 0.30–0.46** как ворота устойчивости; победители в зоне ~0.29–0.31.

### Доказательство честного потолка и его честное преодоление

- **2026-09-10 — 9+1 честных посылок** (`camp_E1..E9.csv`): варьировались фичи (title/deck),
  ключи (4-ключевой + cabin_letter/ticket_prefix), семья модели (RF+ET mixed), bagging, leaf.
  Результат: 6/9 тирьятся с C2, E7 (bagging) и E8 (leaf=20) **ухудшают** до 0.80622.
  Ни одна честная вариация *гиперпараметров/ключей/взвешивания/стекинга* не превзошла 0.81100.
- **2026-09-11 — 9 зондов OOF-stacking** (`stack_S1..S9.csv`): мета-модели (LogReg/RF/ET)
  обучались на out-of-fold вероятностях 3–5 семейных ключей + base-фичи.
  Лучший зонд = **0.80622**, худший = 0.79665. Даже 5-ключевой стек с cvw-признаком не сдвинул потолок.
- **2026-09-13 — прорыв через базовую инженерию фичей** (`att_N3_ageimp.csv`): движок C2
  (RF 3-ключевой cvw, base-фичи) воспроизведён, но базовая фича **Age** вместо грубой
  *глобальной медианы* заполнена **медианой по группе Title×Pclass** (честно, только по train).
  Кандидат отличается от C2 ровно на **2 строки** и дал на реальном LB **0.81578** — потолок 0.81100 пал.
  - N1/N2 (добавление 4-го ключа `cabin_full`/`ticket_num`) дали diff=0 vs C2 и не посылались:
    cvw корректно обнулил слабые ключи; рост дала именно **смена фичи, а не ключа**.
  - **Урок:** перебор гиперпараметров/ключей НЕ эквивалентен перебору базовой инженерии фичей.
    Объявляя «жёсткий потолок», нельзя оставлять нетронутой базовую подготовку данных
    (импутация/кодирование) — это отдельная, часто нетронутая ось роста.
- **2026-09-16 — ВТОРОЙ прорыв через комплементарный сигнал** (`att_px_tp.csv`): движок N3
  воспроизведён, но к base-фичам добавлен **комплементарный family-survival по ПРЕФИКСУ БИЛЕТА**
  (`fs_tp`) — отдельно от основного сигнала по точному билету — как дополнительная фича
  ко всем 3 ключевым моделям. Кандидат отличается от N3 ровно на **2 строки** и дал на реальном
  LB **0.82057** — рекорд 0.81578 пал.
  - `+surv по ФАМИЛИИ` → 0.81100, `+surv по ПАЛУБЕ` → 0.80143: **единственный рабочий
    комплементарный сигнал — префикс билета**; другие группировки вредны (famcomp-ловушка).
  - **Урок:** рост = смена БАЗОВОЙ инженерии/сигнала, не перебор гиперпараметров. Оба прорыва
    (Age Title×Pclass и префикс-сигнал) — именно базовые оси, а не настройка модели.

**Вывод:** честный public LB на выборке 891/418 поднят до **0.82057**. Это по-прежнему
**хрупкий пик** (2-строчное отличие от N3), и дальнейший рост вероятен лишь через *новую честную
инженерию фичей/сигнала*; выше — только утечка/LB-probing/фейк, что категорически запрещено правилами проекта.

## Ключевые находки (грабли)

- Локальный CV **не является** надёжным прокси для LB: глубокие деревья/бустинг дают
  CV 0.84–0.85, но LB 0.74–0.78. Даже добавление разумных фич (Mother/WomanOrChild/Title =
  «famcomp») **систематически** поднимает OOF-CV на +0.003–0.005 (проверено на 16/16 конфигах),
  но на реальном LB **не переносится** — переобучение, невидимое по CV.
- Рекорд — **хрупкий пик**: соседние вариации гиперпараметров (сид/лист/альфа) роняют LB на ~0.007;
  соседние вариации порога предсказания возвращают к ~0.81100.
- **Грабля (2026-09-13):** «доказанный перебором потолок» не абсолютен — базовая
  инженерия фичей (импутация/кодирование) — отдельная ось роста, которую кампании не трогали.
- **Грабля (2026-09-16):** «доказанный» потолок 0.81578 тоже пал через базовую ось —
  комплементарный family-survival по префиксу билета. Но **обобщать на другие группировки нельзя**:
  фамилия и палуба как доп. семейные сигналы вредны (0.81100 / 0.80143). Рабочий сигнал строго специфичен.
- Правило посылок: лучший результат отправляется **последним**, держим ≥1 слот в резерве,
  чтобы лучший счёт остался активным на лидерборде (так и сделано: px_tp послана разведкой, затем
  перепослана финалом).

## Как воспроизвести

```bash
pip install -r requirements.txt

# 1) Базовый артефакт (ET-бленд, 0.80143):
python src/make_blend.py

# 2) RF-бленд (0.80382):
python src/gen_robust.py            # -> robust_rf2.csv

# 3) Финальный рекорд 0.81100 (воспроизводимо, diff=0):
python examples/c2_minimal.py       # -> submissions/c2_minimal.csv

# 4) Рекорд 0.81578 — доимпутация Age (воспроизводимо, diff=0):
python examples/n3_ageimp.py        # -> submissions/n3_ageimp.csv

# 5) НОВЫЙ рекорд 0.82057 — комплементарный family-survival по префиксу билета (diff=0):
python examples/px_tp.py           # -> submissions/px_tp.csv

# Отправка на Kaggle (требует KAGGLE_USERNAME / KAGGLE_KEY):
python -m kaggle competitions submit -c titanic -f submissions/att_px_tp.csv \
  -m "RF 3-key cvw + Age Title x Pclass + complementary ticket-prefix family-survival, public LB 0.82057"
```

> Эталоны воспроизводятся с точностью до строки: `examples/c2_minimal.py` → `cand_3keycvw.csv`
> (diff = 0), `examples/n3_ageimp.py` → `att_N3_ageimp.csv` (diff = 0),
> `examples/px_tp.py` → `att_px_tp.csv` (diff = 0).
